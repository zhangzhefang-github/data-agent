# Domain documentation

This repository uses a single domain context. Read the root `GLOSSARY.md` and the relevant architecture decision records in `docs/adr/` when they exist.

Use the glossary vocabulary in specs, tickets, code, and tests. If a proposal conflicts with an ADR, cite the decision and flag the conflict before changing it.

Use `domain-modeling` when establishing a new domain term or recording an architecture decision. Create the glossary or ADR directory when there is a resolved term or decision to record.
