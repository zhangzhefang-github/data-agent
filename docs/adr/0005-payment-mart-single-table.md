# 支付明细以单表查询进入订单主题空间

2026-11-22，[ADR 0007](0007-readonly-sql-with-fanout.md) 取代下文「拒绝 WITH、子查询和支付表连接订单表」。支付集市一行一笔支付、不复制订单金额、不把 raw 和 staging 放进默认清单，这些仍然成立。

[ADR 0004](0004-customer-order-equijoin.md) 把会放大订单行的支付关系留在授权之外。2026-11-21 决定先开放支付明细的单表查询，仍然不开放这条连接。

支付集市一行一笔支付。列是支付标识、订单标识、支付方式、支付金额，以及从订单复制的订单日期。订单日期用来沿用现有日历；不复制订单金额。物理对象是视图 `payments`，不把 `stg_payments` 或 `raw_payments` 写进空间清单。

关系 `payment_mart_order_mart` 标成会放大行数，汇总键是 `order_id`。带 Fanout 却没有汇总键的模型拒绝发布。空间清单点名支付集市、支付金额和支付笔数，不点名这条关系。提示和执行器因此只允许从支付表做单条 SELECT。支付表与订单表的连接、`WITH`、子查询，以及把支付金额加进订单金额，仍然拒绝。

按支付方式问金额继续用订单上已有的四列。同一轮对话保留多次成功结果，留到订单金额和支付金额要一起回答时再做。
